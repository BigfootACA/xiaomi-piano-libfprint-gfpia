# Fingerprint firmware for the Xiaomi Pad 8 Pro

The driver needs 30 files in `/usr/lib/firmware/qcom/sm8750/xiaomi/piano-fp/`.
They are proprietary Goodix/Xiaomi data and are not part of this repository.
Put them in `firmware/piano-fp/`, which git ignores; `PKGBUILD` refuses to
build unless exactly 30 files are there, and installs them.

| Files | Count | Where they come from |
| --- | ---: | --- |
| `gfpia.mdt`, `gfpia.b00`..`gfpia.b08` | 10 | The signed `gfpia` trusted application, copied unchanged from the device |
| `request-NNNN.bin`, `payload-NNNN.bin` | 20 | Generated by `qcomtee/goodix-gfpia-gen.py` from two models embedded in `libgf_hal.so` |

## The trusted application

`gfpia` is the Goodix TA that the stock HAL drives through
`QSEECom_send_modified_cmd`. It is one of the named images on the `modem`
partition, which Android mounts at `/vendor/firmware_mnt`; locate it with
`find /vendor/firmware_mnt -name 'gfpia.*'`. Copy the metadata file and all
nine segments as they are. `gfpia-tee.c` reassembles them by the program
header offsets in `gfpia.mdt` and loads the result through QTEE's
`loadFromRegion`, because the image is larger than the 4 MiB inline limit.

Use the image from the slot the device actually boots. Every other named TA on
that partition (`fingerpr`, `fpapp`, ...) loads too, but only `gfpia` speaks
the protocol in `qcomtee/goodix-gfpia.md`.

## The initialisation requests

The driver replays ten commands from this directory on every open, each as a
0x80-byte request and its payload:

| Stem | Command | Request token / payload sequence | Payload size |
| --- | --- | --- | ---: |
| `1000` | `GF_CMD_DETECT_SENSOR` | 1 / 0 | 0x280 |
| `1001` | `GF_CMD_INIT` | 2 / 1 | 0x168 |
| `1113-asp-0`..`2` | `GF_CMD_TRANSPORT_DATA`, CAP_S_2 anti-spoofing model | 3..5 / 2..4 | 0x7d014 |
| `1113-palm-0`..`2` | `GF_CMD_TRANSPORT_DATA`, palm mistouch model | 6..8 / 5..7 | 0x7d014 |
| `1005` | `GF_CMD_INIT_FINISHED` | 9 / 8 | 0x74 |
| `1014` | `GF_CMD_SET_ACTIVE_GROUP`, gid 0, `/data/vendor_de/0/fpdata` | 10 / 9 | 0x270 |

The 1113 payloads are the two algorithm models, each split into three
transport chunks. They come from the stock HAL `/odm/lib64/libgf_hal.so`
(Build ID `3e77582c7e2d0f615af1607f6753b2a4`), where they are embedded at
these file offsets:

| Model file | Offset | Size | SHA-256 |
| --- | --- | ---: | --- |
| `piano-goodix-cap-s-2.bin` | `0x39c3e0` | `0x4b540` | `01829194c8a1e00b7bf1cc0440043bc5ee45057791f1f1ab410f8119bc10ae4e` |
| `piano-goodix-mistouch.bin` | `0x094da0` | `0x48c88` | `422741920cb2a0e508241e9d1b7c824f7304f15e638b1576423c6fb99f99ec71` |

Extract them and generate the whole set:

    dd if=libgf_hal.so of=piano-goodix-cap-s-2.bin \
       iflag=skip_bytes,count_bytes skip=$((0x39c3e0)) count=$((0x4b540))
    dd if=libgf_hal.so of=piano-goodix-mistouch.bin \
       iflag=skip_bytes,count_bytes skip=$((0x094da0)) count=$((0x48c88))

    qcomtee/goodix-gfpia-gen.py piano-active-group \
        --cap-s-model piano-goodix-cap-s-2.bin \
        --mistouch-model piano-goodix-mistouch.bin \
        --output-dir piano-active-group-input
    (cd piano-active-group-input && sha256sum -c SHA256SUMS)
    cp piano-active-group-input/*.bin firmware/piano-fp/

The generator checks both models' sizes and hashes and refuses anything else,
so a wrong offset or a different HAL build fails here rather than on the
device. Piano's command-1000 configuration needs both models: chip `0x31`,
palm enabled, ASP enabled, CAP_S rather than CAP_T. Never take the CAP_T_2
model at `0x3e7924` by mistake.

The 1000, 1001 and 1005 payloads carry the time of generation, so the hashes of
a fresh set differ from the deployed ones below. `--time-ms 0` gives the
reference vectors listed in `qcomtee/goodix-gfpia.md`.

## Files the TA writes

The templates are not firmware. The TA writes them through
`qcomtee-fs-supplicant`, which maps its Android paths below
`/var/lib/xiaomi-fingerprint` (for example `data/vendor_de/0/fpdata/`). Back
that directory up before reinstalling. If fingers stop being detected, delete
`/var/lib/xiaomi-fingerprint/data/vendor_de/0/fpdata/gf_fdt_base.so`, the
finger-detect baseline; the driver also does this on every open.
